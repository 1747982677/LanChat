# LanChat 后端接口文档

## 概述

本文档描述了 LanChat 项目的后端接口规范，供前端对接使用。所有接口遵循 Controller-Worker 多线程架构模式。

**重要说明：**
- 所有网络通信相关操作在 `NetworkWorker` 线程中执行
- 所有数据库操作在 `DbLogicWorker` 线程中执行
- UI层通过 `Controller` 调用，严禁直接调用 `Worker` 方法
- 使用信号槽机制进行异步通信

---

## 一、联系人状态管理（任务9, 12）

### 1.1 更新用户在线状态

**Controller接口：** `DbLogicController::updateUserStatus(userId, status)`

**参数：**
- `userId` (QString): 用户ID
- `status` (int): 状态值（0=离线, 1=在线, 2=忙碌）

**信号：** `userStatusUpdated(userId, status)`

**说明：** 更新本地数据库中用户的在线状态。

---

### 1.2 获取好友在线状态

**Controller接口：** `DbLogicController::loadContactList()`

**信号：** `contactListLoaded(contacts)` - contacts 为 QJsonArray，每个元素包含：
```json
{
  "userId": "user_123",
  "nickname": "张三",
  "avatarPath": ":/avatar.jpg",
  "status": 1,  // 0=离线, 1=在线, 2=忙碌
  "lastOnlineTime": 1234567890
}
```

**说明：** 加载联系人列表，包含在线状态信息。

---

### 1.3 在线状态推送（WebSocket）

**消息类型：** `status_update`

**消息格式：**
```json
{
  "type": "status_update",
  "userId": "user_123",
  "status": 1,  // 0=离线, 1=在线, 2=忙碌
  "timestamp": 1234567890
}
```

**说明：** 通过 WebSocket 实时推送好友状态变化。心跳机制和 UDP 广播在 `NetworkWorker` 中自动维护。

## 二、好友管理（任务10）

### 2.1 通过账号搜索用户

**Controller接口：** `DbLogicController::searchUserByAccount(account)`

**参数：**
- `account` (QString): 账号（精确匹配，不支持模糊查询）

**信号：** `userSearchResult(userInfo, found)`
- `userInfo` (QJsonObject): 用户信息（如果找到）
- `found` (bool): 是否找到

**用户信息格式：**
```json
{
  "userId": "user_123",
  "account": "user@example.com",
  "nickname": "张三",
  "avatarPath": ":/avatar.jpg",
  "email": "user@example.com",
  "phone": "13800138000",
  "signature": "个性签名"
}
```

---

### 2.2 发送好友请求

**Controller接口：** `DbLogicController::sendFriendRequest(requestInfo)`

**参数：** `requestInfo` (QJsonObject)
```json
{
  "senderId": "user_123",
  "receiverId": "user_456",
  "senderAccount": "user@example.com",
  "senderNickname": "张三",
  "avatarPath": ":/avatar.jpg",
  "verifymsg": "我是张三，请求添加好友"
}
```

**信号：** `friendRequestSent(success, requestId, error)`
- `success` (bool): 是否成功
- `requestId` (QString): 请求ID（成功时）
- `error` (QString): 错误信息（失败时）

**说明：** 
- 保存好友请求到数据库
- 通过 WebSocket 发送请求给接收方

---

### 2.3 获取好友请求列表

**Controller接口：** `DbLogicController::getFriendRequests(userId)`

**参数：**
- `userId` (QString): 当前用户ID

**信号：** `friendRequestsLoaded(requests)` - requests 为 QJsonArray，每个元素：
```json
{
  "requestId": "req_123",
  "senderId": "user_123",
  "senderAccount": "user@example.com",
  "senderNickname": "张三",
  "avatarPath": ":/avatar.jpg",
  "verifymsg": "我是张三，请求添加好友",
  "status": 0,  // 0=待处理, 1=已接受, 2=已拒绝
  "timestamp": 1234567890
}
```

---

### 2.4 处理好友请求（同意/拒绝）

**Controller接口：** `DbLogicController::handleFriendRequest(requestId, accept)`

**参数：**
- `requestId` (QString): 请求ID
- `accept` (bool): true=同意, false=拒绝

**信号：** `friendRequestHandled(success, requestId, accepted)`

**说明：** 
- 如果同意，会在 `friends` 表中建立双向好友关系
- 通过 WebSocket 通知发送方处理结果

---

### 2.5 删除好友

**Controller接口：** `DbLogicController::deleteFriend(userId, friendId)`

**参数：**
- `userId` (QString): 当前用户ID
- `friendId` (QString): 好友ID

**信号：** `friendDeleted(success, friendId)`

**说明：** 删除双向好友关系。

---

## 三、消息收发与记录（任务11）

### 3.1 发送消息

**Controller接口：** `NetworkController::sendMessage(message)`

**参数：** `message` (QJsonObject)
```json
{
  "type": "chat_message",
  "messageId": "msg_123",
  "senderId": "user_123",
  "receiverId": "user_456",
  "content": "消息内容",
  "timestamp": 1234567890
}
```

**信号：** 
- `messageSendSuccess(messageId)` - 发送成功
- `messageSendFailed(messageId, reason)` - 发送失败

**说明：** 
- 消息先保存到数据库（状态=Pending）
- 通过 WebSocket 发送
- 收到服务器确认后更新状态为 Sent
- 如果失败，状态更新为 Failed

---

### 3.2 接收消息

**信号：** `NetworkController::messageReceived(message, from)`

**参数：**
- `message` (QJsonObject): 消息内容（格式同发送消息）
- `from` (QString): 发送方地址（ip:port）

**说明：** 
- 自动保存到数据库
- 更新会话的 `lastMessage` 和 `lastTime`
- 增加未读消息计数

---

### 3.3 加载聊天记录

**Controller接口：** `DbLogicController::loadHistoryMessages(contactId, limit, offset)`

**参数：**
- `contactId` (QString): 联系人ID
- `limit` (int): 每页数量（默认50）
- `offset` (int): 偏移量（默认0）

**返回值：** `requestId` (QString) - 用于验证响应

**信号：** `historyMessagesLoaded(requestId, messages, contactId)`
- `requestId` (QString): 请求ID（用于验证）
- `messages` (QJsonArray): 消息列表（按时间倒序）
- `contactId` (QString): 联系人ID

**消息格式：**
```json
{
  "messageId": "msg_123",
  "senderId": "user_123",
  "receiverId": "user_456",
  "content": "消息内容",
  "type": 0,  // 0=文本, 1=图片, 2=语音, 99=系统
  "status": 1,  // 0=发送中, 1=已发送, 2=已读, 3=失败
  "timestamp": 1234567890
}
```

**重要：** 使用 Request ID 机制防止数据错乱，前端必须验证 `requestId` 是否匹配。

---

### 3.4 搜索消息

**Controller接口：** `DbLogicController::searchMessages(keyword)`

**参数：**
- `keyword` (QString): 搜索关键词

**信号：** `searchResultsReady(results)` - results 为 QJsonArray，每个元素：
```json
{
  "messageId": "msg_123",
  "senderId": "user_123",
  "receiverId": "user_456",
  "content": "包含关键词的消息内容",
  "timestamp": 1234567890,
  "contactId": "user_123",  // 会话对方ID
  "contactName": "张三"     // 会话对方昵称
}
```

**说明：** 在所有会话中模糊搜索文本消息。

---

### 3.5 获取未读消息数量

**Controller接口：** `DbLogicController::getUnreadCount(userId, contactId)`

**参数：**
- `userId` (QString): 当前用户ID
- `contactId` (QString): 联系人ID（如果为空，返回所有会话的未读总数）

**信号：** `unreadCountLoaded(contactId, count)`

---

### 3.6 标记会话为已读

**Controller接口：** `DbLogicController::markSessionAsRead(userId, contactId)`

**参数：**
- `userId` (QString): 当前用户ID
- `contactId` (QString): 联系人ID

**信号：** `sessionMarkedAsRead(contactId, success)`

**说明：** 
- 清零该会话的未读消息计数
- 通过 WebSocket 通知发送方消息已读
- 更新数据库中消息状态为已读

---

### 3.7 更新消息状态

**Controller接口：** `DbLogicController::updateMessageStatus(messageId, status)`

**参数：**
- `messageId` (QString): 消息ID
- `status` (QString): 状态字符串（"pending", "sent", "read", "failed"）

**信号：** `messageStatusUpdated(success, messageId)`

## 四、WebSocket 消息协议

### 4.1 消息类型

所有 WebSocket 消息都是 JSON 格式，包含 `type` 字段：

| 类型 | 说明 |
|------|------|
| `chat_message` | 聊天消息 |
| `friend_request` | 好友请求 |
| `friend_request_response` | 好友请求响应 |
| `status_update` | 状态更新 |
| `message_read` | 消息已读通知 |
| `heartbeat` | 心跳包 |

### 4.2 心跳机制

- 客户端每 10 秒发送一次 `ping`
- 服务器响应 `pong`
- 连续 3 次未收到 `pong` 则判定为断线，触发重连

### 4.3 UDP 广播（局域网状态同步）

- UDP 端口：45454（默认）
- 广播间隔：5 秒
- 用于局域网内发现其他在线用户

## 五、使用示例

### 5.1 发送消息示例

```cpp
// UI层
QJsonObject msg;
msg["type"] = "chat_message";
msg["messageId"] = QUuid::createUuid().toString();
msg["senderId"] = currentUserId;
msg["receiverId"] = contactId;
msg["content"] = "Hello";
msg["timestamp"] = QDateTime::currentMSecsSinceEpoch();

NetworkController::instance().sendMessage(msg);

// 连接信号
connect(&NetworkController::instance(), &NetworkController::messageSendSuccess,
        this, [](const QString& msgId) {
    qDebug() << "消息发送成功:" << msgId;
});
```

### 5.2 加载聊天记录示例

```cpp
// UI层
QString requestId = DbLogicController::instance().loadHistoryMessages(contactId, 50, 0);

// 连接信号（注意验证 requestId）
connect(&DbLogicController::instance(), &DbLogicController::historyMessagesLoaded,
        this, [requestId](const QString& respRequestId, const QJsonArray& messages, const QString& contactId) {
    // 验证 requestId 是否匹配
    if (respRequestId != requestId) {
        qWarning() << "Request ID 不匹配，忽略响应";
        return;
    }
    
    // 处理消息列表
    for (const auto& msgValue : messages) {
        QJsonObject msg = msgValue.toObject();
        // 显示消息...
    }
});
```

## 六、错误处理

所有操作失败时，会通过相应的信号返回错误信息。前端应监听这些信号并显示错误提示。

常见错误：
- 数据库未初始化
- 网络连接失败
- 用户不存在
- 重复的好友请求
- 消息发送超时

---

## 七、注意事项

1. **线程安全：** 所有数据库操作在 `DbLogicWorker` 线程中执行，网络操作在 `NetworkWorker` 线程中执行
2. **Request ID：** 加载聊天记录时必须使用 Request ID 机制，防止数据错乱
3. **状态同步：** 消息状态更新会通过 WebSocket 实时同步
4. **心跳维护：** 心跳和重连机制在 `NetworkWorker` 中自动处理，无需手动管理
5. **UDP 广播：** UDP 广播用于局域网发现，不影响 WebSocket 通信
