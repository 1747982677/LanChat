# LanChat 多线程架构使用指南

## 架构概述

本项目采用 **Controller-Worker** 多线程模式，分为三个核心线程：

```
┌─────────────────────────────────────────────────────────┐
│                    UI 主线程 (Main Thread)              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ MainWindow   │  │  Network     │  │  DbLogic     │  │
│  │              │  │  Controller  │  │  Controller  │  │
│  └──────────────┘  └──────┬───────┘  └──────┬───────┘  │
└───────────────────────────┼──────────────────┼──────────┘
                            │                  │
                     信号槽通信           信号槽通信
                            │                  │
┌───────────────────────────┼──────────────────┼──────────┐
│  网络线程                  ▼                  │           │
│  ┌──────────────────────────┐                │           │
│  │   Network Worker         │                │           │
│  │  - 消息收发               │                │           │
│  │  - 连接管理               │                │           │
│  │  - 心跳维护               │                │           │
│  └──────────────────────────┘                │           │
└──────────────────────────────────────────────┼──────────┘
                                               │
┌──────────────────────────────────────────────┼──────────┐
│  数据库与业务逻辑线程                          ▼           │
│  ┌──────────────────────────┐                           │
│  │   DbLogic Worker         │                           │
│  │  - 数据库操作             │                           │
│  │  - 业务逻辑处理           │                           │
│  │  - 文件处理               │                           │
│  └──────────────────────────┘                           │
└─────────────────────────────────────────────────────────┘
```

## 核心类说明

### 1. 基础类

#### BaseController (基类)
- **位置**: `src/core/base_controller.h`
- **职责**: 所有 Controller 的基类，管理 Worker 线程生命周期
- **运行线程**: 主线程

#### BaseWorker (基类)
- **位置**: `src/core/base_worker.h`
- **职责**: 所有 Worker 的基类，执行具体任务
- **运行线程**: 独立线程

### 2. 网络模块

#### NetworkController
- **位置**: `src/core/network_controller.h`
- **职责**: 网络通信控制器，运行在主线程
- **功能**:
  - 连接/断开服务器
  - 发送消息
  - 启动/停止服务器模式
  - 转发网络事件
  - **🆕 消息发送状态追踪**（成功/失败回调）

#### NetworkWorker
- **位置**: `src/core/network_worker.h`
- **职责**: 网络通信 Worker，运行在网络线程
- **功能**:
  - WebSocket 连接管理
  - 消息收发
  - 心跳维护
  - **🆕 发送结果通知**（messageSendSuccess / messageSendFailed）

### 3. 数据库与业务逻辑模块

#### DbLogicController
- **位置**: `src/core/dblogic_controller.h`
- **职责**: 数据库与业务逻辑控制器，运行在主线程
- **功能**:
  - 数据库操作接口
  - 消息管理
  - 联系人管理
  - 文件处理
  - **🆕 请求ID生成**（防止异步回调错乱）

#### DbLogicWorker
- **位置**: `src/core/dblogic_worker.h`
- **职责**: 数据库与业务逻辑 Worker，运行在独立线程
- **功能**:
  - 数据库增删改查
  - 历史消息加载
  - 消息搜索
  - 文件压缩/转码
  - **🆕 请求ID追踪**（确保回调对应正确的请求）

### 4. 全局上下文

#### AppContext
- **位置**: `src/core/app_context.h`
- **职责**: 全局应用上下文管理器（单例）
- **功能**:
  - 统一管理所有 Controller
  - 协调模块间交互
  - 应用生命周期管理
  - **🆕 消息状态自动管理**（发送成功/失败自动更新数据库）

## 使用方法

### 1. 在 main.cpp 中初始化

```cpp
#include "core/app_context.h"

int main(int argc, char* argv[])
{
    QApplication app(argc, argv);

    // 初始化应用上下文
    AppContext& context = AppContext::instance();
    
    // 设置数据库路径
    context.setDatabasePath("path/to/your/database.db");
    
    // 初始化所有模块
    if (!context.initialize()) {
        qCritical() << "Failed to initialize application";
        return -1;
    }
    
    // 启动所有线程
    context.startAll();
    
    // 初始化数据库（在 Worker 线程中执行）
    context.dbLogicController()->initializeDatabase(context.databasePath());
    
    // 显示主窗口
    MainWindow::instance()->show();
    
    int result = app.exec();
    
    // 停止所有线程
    context.stopAll();
    
    return result;
}
```

### 2. 在 UI 中使用网络功能

```cpp
#include "core/app_context.h"

class MyWidget : public QWidget
{
    Q_OBJECT
public:
    MyWidget(QWidget* parent = nullptr) : QWidget(parent)
    {
        // 获取网络控制器
        NetworkController* netCtrl = AppContext::instance().networkController();
        
        // 连接信号
        connect(netCtrl, &NetworkController::connected, this, [this]() {
            qDebug() << "连接成功！";
        });
        
        connect(netCtrl, &NetworkController::messageReceived, 
                this, &MyWidget::onMessageReceived);
        
        // 🆕 监听消息发送结果
        connect(netCtrl, &NetworkController::messageSendSuccess,
                this, &MyWidget::onMessageSendSuccess);
        connect(netCtrl, &NetworkController::messageSendFailed,
                this, &MyWidget::onMessageSendFailed);
    }
    
    void connectToServer()
    {
        NetworkController* netCtrl = AppContext::instance().networkController();
        netCtrl->connectToServer("192.168.1.100", 8080);
    }
    
    void sendMessage(const QString& text)
    {
        QJsonObject msg;
        msg["messageId"] = QUuid::createUuid().toString();
        msg["content"] = text;
        msg["status"] = "sending";
        
        // 先保存到数据库
        AppContext::instance().dbLogicController()->saveMessage(msg);
        
        // 再发送
        AppContext::instance().networkController()->sendMessage(msg);
    }
    
private slots:
    void onMessageReceived(const QJsonObject& message, const QString& from)
    {
        qDebug() << "收到消息来自" << from << ":" << message;
    }
    
    // 🆕 发送成功回调
    void onMessageSendSuccess(const QString& messageId)
    {
        qDebug() << "消息发送成功：" << messageId;
        // 更新 UI 显示对勾
    }
    
    // 🆕 发送失败回调
    void onMessageSendFailed(const QString& messageId, const QString& reason)
    {
        qWarning() << "消息发送失败：" << messageId << reason;
        // 更新 UI 显示重试按钮
    }
};
```

### 4. 发送消息完整流程（带状态管理）

```cpp
void sendChatMessage(const QString& text, const QString& toUserId)
{
    // 1. 生成消息ID
    QString messageId = QUuid::createUuid().toString(QUuid::WithoutBraces);
    
    // 2. 构造消息对象
    QJsonObject message;
    message["messageId"] = messageId;
    message["senderId"] = "me";
    message["receiverId"] = toUserId;
    message["content"] = text;
    message["timestamp"] = QDateTime::currentMSecsSinceEpoch();
    message["status"] = "sending";  // 🆕 初始状态为 sending
    
    // 3. 立即保存到数据库（状态：sending）
    AppContext::instance().dbLogicController()->saveMessage(message);
    
    // 4. 立即在UI显示（显示转圈圈）
    addMessageToUI(message, true);
    
    // 5. 通过网络发送
    AppContext::instance().networkController()->sendMessage(message);
    
    // 🆕 后续自动处理：
    // - 成功：AppContext 收到 messageSendSuccess 信号，更新状态为 "sent"
    // - 失败：AppContext 收到 messageSendFailed 信号，更新状态为 "failed"
}
```

### 5. 接收消息完整流程

在 `AppContext` 中已经自动处理了：

```cpp
// AppContext::connectControllers() 中
void AppContext::connectControllers()
{
    if (m_networkController && m_dbLogicController) {
        // 收到网络消息 -> 自动保存到数据库
        connect(m_networkController, &NetworkController::messageReceived,
                this, [this](const QJsonObject& message, const QString& from) {
                    QJsonObject fullMessage = message;
                    fullMessage["from"] = from;
                    fullMessage["timestamp"] = QDateTime::currentDateTime().toString(Qt::ISODate);
                    fullMessage["status"] = "received";
                    
                    m_dbLogicController->saveMessage(fullMessage);
                });

        // 🆕 消息发送成功 -> 更新数据库状态
        connect(m_networkController, &NetworkController::messageSendSuccess,
                this, [this](const QString& messageId) {
                    qDebug() << "消息发送成功，更新状态：" << messageId;
                    m_dbLogicController->updateMessageStatus(messageId, "sent");
                });

        // 🆕 消息发送失败 -> 更新数据库状态为失败
        connect(m_networkController, &NetworkController::messageSendFailed,
                this, [this](const QString& messageId, const QString& reason) {
                    qWarning() << "消息发送失败：" << messageId << reason;
                    m_dbLogicController->updateMessageStatus(messageId, "failed");
                    emit applicationError(QString("消息发送失败: %1").arg(reason));
                });
    }
}
```

### 6. UI 中的完整使用示例

```cpp
class ChatWindow : public QWidget
{
    Q_OBJECT
public:
    ChatWindow(QWidget* parent = nullptr) : QWidget(parent)
    {
        setupConnections();
    }

private:
    QString m_currentContactId;      // 当前聊天的联系人 ID
    QString m_currentLoadRequestId;  // 🆕 当前加载请求的 ID
    
    void setupConnections()
    {
        // 🆕 监听历史消息加载，验证 requestId
        connect(&AppContext::instance().dbLogicController(),
                &DbLogicController::historyMessagesLoaded,
                this,
                &ChatWindow::onHistoryLoaded);

        // 监听消息状态更新
        connect(&AppContext::instance().dbLogicController(),
                &DbLogicController::messageStatusUpdated,
                this,
                &ChatWindow::onMessageStatusUpdated);
    }

    // 用户切换到某个好友的聊天窗口
    void openChat(const QString& userId)
    {
        qDebug() << "Opening chat with:" << userId;

        // 1. 清空当前显示
        clearMessageList();

        // 2. 更新当前联系人 ID
        m_currentContactId = userId;

        // 3. 🆕 发起加载请求，保存 requestId
        m_currentLoadRequestId = AppContext::instance()
            .dbLogicController()
            ->loadHistoryMessages(userId, 50, 0);

        qDebug() << "Issued load request:" << m_currentLoadRequestId;
    }

    // 🆕 收到历史消息时，验证 requestId
    void onHistoryLoaded(const QString& requestId, 
                         const QJsonArray& messages, 
                         const QString& contactId)
    {
        qDebug() << "History loaded - requestId:" << requestId 
                 << "currentRequestId:" << m_currentLoadRequestId
                 << "contactId:" << contactId;

        // 🆕 关键检查：只处理当前请求的数据
        if (requestId != m_currentLoadRequestId) {
            qWarning() << "Ignoring stale history data for:" << contactId;
            return;  // 丢弃过期的数据
        }

        // 确保联系人也匹配
        if (contactId != m_currentContactId) {
            qWarning() << "Contact ID mismatch, ignoring";
            return;
        }

        // ✅ 验证通过，显示消息
        qDebug() << "Displaying" << messages.size() << "messages";
        displayMessages(messages);
    }

    // 发送消息
    void sendMessage(const QString& text)
    {
        // 1. 生成消息 ID
        QString messageId = QUuid::createUuid().toString(QUuid::WithoutBraces);

        // 2. 构造消息对象
        QJsonObject msg;
        msg["messageId"] = messageId;
        msg["senderId"] = "me";
        msg["receiverId"] = m_currentContactId;
        msg["content"] = text;
        msg["timestamp"] = QDateTime::currentMSecsSinceEpoch();
        msg["status"] = "sending";  // 初始状态为 sending

        // 3. 立即保存到数据库（状态：sending）
        AppContext::instance()
            .dbLogicController()
            ->saveMessage(msg);

        // 4. 立即在 UI 显示（显示转圈圈）
        addMessageToUI(msg, true);  // true = 显示发送中动画

        // 5. 发送到网络
        AppContext::instance()
            .networkController()
            ->sendMessage(msg);

        // 🆕 后续自动处理：
        // - 发送成功：AppContext 收到 messageSendSuccess 信号，更新状态为 "sent"
        // - 发送失败：AppContext 收到 messageSendFailed 信号，更新状态为 "failed"
    }

    // 🆕 消息状态更新回调
    void onMessageStatusUpdated(bool success, const QString& messageId)
    {
        if (success) {
            qDebug() << "Message status updated:" << messageId;
            updateMessageStatusInUI(messageId);
        } else {
            qWarning() << "Failed to update message status:" << messageId;
        }
    }

    void updateMessageStatusInUI(const QString& messageId)
    {
        // 根据消息 ID 找到对应的气泡，更新显示
        // - "sending" -> 显示转圈圈 ⏳
        // - "sent" -> 显示单个对勾 ✓
        // - "delivered" -> 显示双对勾 ✓✓
        // - "read" -> 显示蓝色双对勾 ✓✓
        // - "failed" -> 显示红色叹号 ❌ + 重试按钮
    }

    void clearMessageList() { /* 清空消息列表 UI */ }
    void displayMessages(const QJsonArray& messages) { /* 显示消息列表 */ }
    void addMessageToUI(const QJsonObject& message, bool showLoading) { /* 添加消息到 UI */ }
};
```

## 🆕 功能说明

### 1. 消息发送状态追踪

**问题**：网络发送失败时，数据库中的消息状态永远停留在 "sending"，导致 UI 显示"幽灵消息"。

**解决方案**：
- `NetworkWorker` 发送消息后，根据结果发出 `messageSendSuccess` 或 `messageSendFailed` 信号
- `AppContext` 监听这些信号，自动更新数据库中的消息状态
- UI 监听 `messageStatusUpdated` 信号，更新消息气泡显示

**消息状态流转**：
```
sending (发送中) → sent (已发送) → delivered (已送达) → read (已读)
               ↘ failed (发送失败)
```

### 2. 异步查询请求ID机制

**问题**：用户快速切换聊天窗口时，先发出的查询后返回，导致显示错误联系人的消息。

**解决方案**：
- `DbLogicController::loadHistoryMessages()` 返回一个唯一的 `requestId`
- UI 保存当前的 `requestId`
- 收到 `historyMessagesLoaded` 信号时，验证 `requestId` 是否匹配当前请求
- 只有匹配的请求才会显示，过期的请求被丢弃

**典型场景**：
```
1. 用户打开张三聊天 -> requestId = "req-001"
2. 数据库开始查询张三的记录（耗时200ms）
3. 用户切换到李四聊天 -> requestId = "req-002"
4. 数据库返回张三的数据（requestId = "req-001"）
5. UI 检查："req-001" != "req-002" -> 丢弃数据 ✅
6. 数据库返回李四的数据（requestId = "req-002"）
7. UI 检查："req-002" == "req-002" -> 显示数据 ✅
```

## 线程安全说明

### ✅ 安全的操作
- 所有通过 Controller 的方法调用（会通过信号槽自动切换到 Worker 线程）
- 从 Worker 发出的信号（会自动切换回主线程）
- JSON 对象作为参数传递（Qt 会自动拷贝）

### ❌ 不安全的操作
- 直接访问 Worker 对象
- 在主线程中调用 Worker 的方法
- 在 Worker 线程中直接操作 UI
- 共享指针或引用（除非有互Mutex保护）

### 正确的通信方式
```cpp
// ✅ 正确：通过 Controller
AppContext::instance().networkController()->sendMessage(msg);

// ❌ 错误：直接访问 Worker
// NetworkWorker* worker = ...; 
// worker->sendMessage(msg);  // 危险！可能在错误的线程中执行
```

## 添加新功能

在 `NetworkWorker` 和 `NetworkController` 中添加：


## 注意事项

1. **不要阻塞主线程**：所有耗时操作都应该在 Worker 线程中执行
2. **使用信号槽通信**：Controller 和 Worker 之间只能通过信号槽通信
3. **避免共享数据**：如果必须共享，使用 `QMutex` 保护
4. **合理使用 JSON**：用于模块间传递复杂数据
5. **错误处理**：监听 `errorOccurred` 信号处理错误
6. **🆕 保存请求ID**：异步查询时要保存 requestId 并验证
7. **🆕 处理发送失败**：监听 messageSendFailed 信号，显示重试按钮

## 性能优化建议

1. **批量操作**：多个数据库操作可以合并为一个事务
2. **消息队列**：高频消息可以先缓存，批量发送
3. **数据缓存**：常用数据可以在主线程缓存，减少查询
4. **异步加载**：大量历史消息分页加载
5. **🆕 请求去重**：防止重复发起相同的查询请求
6. **🆕 状态更新批处理**：多个状态更新可以合并为一次数据库操作

## 常见问题排查

### Q1: 消息一直显示"发送中"，不消失？

**A**: 检查是否监听了 `messageSendSuccess` 和 `messageSendFailed` 信号，以及 `AppContext` 中的状态更新逻辑是否正确。

### Q2: 切换聊天窗口时显示了错误的消息？

**A**: 确保在收到 `historyMessagesLoaded` 信号时，验证了 `requestId` 是否匹配当前请求。

### Q3: UI 更新不及时？

**A**: 确保 Worker 的信号已经连接到 Controller，并且 Controller 的信号已经转发给 UI。

### Q4: 程序崩溃或死锁？

**A**: 检查是否在 Worker 线程中直接操作了 UI，或者在主线程中直接调用了 Worker 的方法。

## 总结

架构提供了：
-  清晰的模块分离
-  线程安全的通信
-  易于扩展的接口
-  统一的错误处理
-  灵活的业务逻辑编排
- 可靠的消息发送状态管理
- 准确的异步查询结果匹配

使用时只需通过 `AppContext` 获取对应的 Controller，调用其方法即可，无需关心底层的线程管理、状态追踪和请求匹配逻辑。
